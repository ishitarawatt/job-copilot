# Guardrails

All guardrails live in `src/copilot/guardrails.py` and are **deterministic code**.

| # | Risk | Control | Where | Test |
|---|---|---|---|---|
| G1 | Fabricated experience | Every output bullet must match a source bullet (≥80% token overlap) and introduce **no new numbers**; claimed skills must appear in the source as a whole word or phrase | Critic | `test_fabrication_detects_*`, eval `fabrication_*` |
| G1b | Strengthened claims | A bullet may not add an ownership/scope/seniority word (led, managed, spearheaded, entire, senior, sole, …) that its source bullet lacks, even at high overlap ("Used SQL dashboards" → "Led SQL dashboards") | Critic | `test_strengthened_*`, `test_scope_and_seniority_*`, evals `inflated_verb_*`, `persistent_inflation_*` |
| G1d | Skill evidence is whole-word | A claimed skill counts as evidenced only if it appears as a whole word or phrase: "java" is not evidenced by "javascript", "rag" by "leveraged", or "excel" by "excellent". The same rule drives the gap report | Critic, Tailor mock | `test_skill_in_text_*`, `test_critic_rejects_skill_only_evidenced_*`, `test_gap_report_*`, evals `backend_java_is_not_javascript`, `ml_rag_is_not_leveraged`, `ops_excel_is_not_excellent` |
| G1c | Summary embellishment | The summary is held to the same rules: no numbers absent from the source resume, no added strength words. The target job title is exempt so the summary can name the role | Critic | `test_summary_*`, evals (summary is part of `fabrication_rate`) |
| G2 | Prompt injection in JD | Lines matching injection patterns are dropped; run continues on the remainder; flag `prompt_injection_removed` | Input | `test_injection_line_removed_*`, eval `prompt_injection_in_jd` |
| G2b | Obfuscated / paraphrased / multilingual injection | Text is normalised first (zero-width characters removed, full-width and accented letters folded), then matched against a wider pattern set (forget/override/new-instructions, persona hijack, verdict steering, chat-template markers, ES/FR/DE "ignore previous instructions"); instructions split across two lines are caught; a clean line next to an injected one is kept | Input | `test_injection_variants_removed`, `test_injection_split_*`, `test_clean_line_next_to_injection_is_kept`, `test_ordinary_job_text_is_not_flagged`, eval `prompt_injection_obfuscated` |
| G3 | PII exposure | Emails/phones redacted from the resume before any model call; evals assert none appear in output | Input | `test_resume_pii_not_in_output`, eval `pii_leak_rate` |
| G3b | More PII types | URLs (incl. LinkedIn/GitHub/etc.), @handles and capitalised street addresses are also redacted; ordinary text ("5 experiments to drive growth", "Node.js") is left alone | Input | `test_redact_urls_handles_addresses`, `test_redaction_leaves_ordinary_*`, eval `pii_urls_and_addresses_redacted` |
| G4 | ATS score can't reward invention | The ATS-style score (`ats.py`) is code, computed only from the Critic-approved resume (`None` when withheld). Keywords count only as whole-word evidence, so listing skills you lack cannot raise it; it is advisory and never blocks or alters output | Output | `test_ats_keywords_only_count_*`, `test_ats_does_not_count_a_longer_word_*`, `test_ats_is_set_only_for_an_approved_resume`, parity `test_ats_score_matches`, eval gate `ats_invalid_rate` |
| G4 | Garbage in | JD < 40 chars or resume with no bullets → `blocked` with reason | Input | eval `*_blocked` |
| G5 | Oversized input / cost abuse | JD truncated at 12,000 chars; flag `jd_truncated` | Input | unit |
| G6 | Malformed model output | Parsed into typed dataclasses; 2 retries then escalate | Agents | `test_malformed_output_*` |
| G7 | Unverifiable result | Fail closed: resume withheld, status `needs_human` | Orchestrator | `test_persistent_fabrication_*` |
| G8 | Runaway loops/cost | Hard retry and critic-loop caps | Orchestrator | constants + tests |

## Known gaps (be honest about these)
- **Pattern-based injection detection is still evadable.** Normalisation and a wider pattern set raise the bar, but paraphrases we have no pattern for, other languages beyond ES/FR/DE, homoglyphs (e.g. Cyrillic look-alikes), letter-spacing (`i g n o r e`) and leetspeak all get through. Defense in depth is the point: the Analyzer's prompt marks JD text as data, and the critic validates outputs regardless of what the model was told. Note `system prompt` is a blunt pattern and can drop a legitimate line in a JD about LLM work.
- The ATS score is a heuristic (keyword coverage, numbers in bullets, structure, bullet length). It is not any real ATS's score and cannot see layout, fonts or file format. Skill matching is whole-word, so inflected forms ("designed" vs "design") count as missing.
- **Resume text is not scanned for injection.** Only the JD is. The resume is the user's own input, but a pasted resume can contain hostile text; the critic still validates every output bullet against it.
- **Fabrication check is lexical, now with a word list.** The strength-word list (`_INFLATION_FAMILIES` in `guardrails.py`) catches the common inflations, but it is a list: a stronger claim expressed with a word not on it ("headlined", "delivered end to end") still passes, and number words ("four" vs "4") are not compared. It is also strict by design, so a legitimate rephrase that introduces a listed word is rejected and may cost a critic loop or a `needs_human`. Add a semantic judge as a second signal and sample human audits.
- **Skill matching is exact, so it is strict.** Inflected forms do not match ("API designs" does not evidence `api design`), so a legitimate skill claim can be rejected. That fails closed (a critic loop or `needs_human`), not open. A stemmer or alias table would fix it; neither exists yet.
- **Resume size is not capped.** `MAX_RESUME_BULLETS` is defined in `guardrails.py` but never enforced, so a very long resume goes to the model in full (G5 covers the job description only).
- **Regex PII redaction** misses names, non-English street names, bare domains without a scheme (`janedoe.dev`) and postal codes. Addresses are matched only when capitalised with a known street word. Use a dedicated PII service before handling real user data at scale.
- The resume header (name) is not sent to the model by design, but free-text sections could contain other identifiers.
- All of the above are measured against the offline mock model. They validate the harness and the deterministic guards, not live-model behaviour; run `evals/run_evals.py --live` before trusting results.
